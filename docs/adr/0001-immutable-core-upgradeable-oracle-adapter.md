# ADR-0001：不可变核心 + 可升级 oracle 适配器

- **状态**：已采纳（Accepted）
- **日期**：2026-10-07
- **背景来源**：`docs/contract-review.md`（10 项发现）+ 合约原地升级可行性评估

## 背景

合约审查修出 10 项发现，全部**只能通过重新部署**上链 —— 因为全代码库**没有任何 `SetCode` / 升级路径**（已核实）。每个合约改动 = 新地址，会波及站点 / API / Mini App / 文档 / 集成方，并且**孤立已有代币供应**（本次侥幸：PLT `totalSupply = 0`，尚无供应）。

于是产生一个架构抉择：**要不要给合约加"原地升级"能力？**

## 决策

**不给持有价值 / 定义规则的合约加任何原地升级通道。** 具体分层：

| 层 | 合约 | 可升级性 | 理由 |
|---|---|---|---|
| 核心价值层 | `PlanetCore`、PLT/PLTG `JettonMinter`、`PlanetBond`、`PlanetFund` | **永久不可变** | 升级权 = 能改 PPI 公式 / 无限增发 / 转走储备 = 主密钥风险 |
| 治理层 | `PlanetGov`、`PlanetTimelock` | **永久不可变** | 治理本身被升级 = 治理可被单方改写 |
| 适配层 | **oracle 适配器（待建，且不持有任何资金）** | **可升级** | 价格源会换代（RedStone/DIA、签名方案）；不托管价值 ⇒ 风险降一个量级 |

**参数变化不靠升级**：篮子 / 权重 / oracle 地址 / 签名者 / 限额 / 费率 / 暂停 全部已是 owner(时间锁) 可改的消息，**无需改代码**。

**"改逻辑"走迁移而非换码**：正式、可审计的 **redeploy + 搬余额** runbook（见 `docs/deploy-runbook.md`），不是隐蔽替换 code cell。

### 若将来确实要给持值合约加升级
必须**同时**具备，缺一不可：

1. owner = **多签（2/3+）**，且多签自身置于时间锁之后；
2. **时间锁延时 ≥ 48h**（升级 = 退出窗口，这是最重要的一条缓解）；
3. **代码哈希先链上承诺**（`proposeCode(hash)` → 到期校验哈希一致才 `applyCode`），防最后一秒换 payload；
4. **链上事件 + 监控告警**，门户/UI 显式提示"计划变更"；
5. **日落条款**（如 TVL 超阈值或到某日期后永久冻结升级权）。

## 后果

**收益**
- 信任模型保持"**信任代码**"，与协议"可验证、非托管"的核心叙事一致；
- 没有主密钥：偷一把 admin key 不能重写规则 / 增发 / 搬库；
- 审计范围**稳定且有终局**（审计过的代码就是运行的代码）；
- 可信中立：不能被强制冻结/改写。

**代价**
- 修 bug 需要**重新部署 + 迁移**：地址全变、要搬余额、要更新所有集成；
- 必须维持一份**严谨的迁移 runbook**，否则迁移本身成为最大风险点；
- 无法"紧急热修"。

## 已记录的相关决策点

- **新鲜度 vs 成本**（oracle）：采用 **每日推送 + API/监控 SLA 放宽到 26h**（最省 gas）。链上 `MAX_ORACLE_AGE = 6h` **保持不动** —— 它是**铸造安全护栏**（价格陈旧即拒绝铸造），与"pipeline 新鲜度 SLA"是两件事，不得混淆。
  - 功能性后果：每日推送下，**每天只有推送后 6 小时内可铸造**。PoC 阶段（supply=0）可接受；真实使用前须提高推送频率或重新评估该护栏。
- **合约会把附带 TON 永久困死**（今天 Core 里压着 1.63 TON）：主网前降低附带值 + 给合约加 owner 可扫出路径。

## 后续工作

1. 落地 **oracle 适配器**拆分（零资金、可升级；Core 侧保留 6h 新鲜度 + 15% 偏离带 + M-of-N 签名作为兜底）。
2. **per-asset 陈旧度**：当前陈旧度是**全局**的（`lastOracleUpdate`）—— 更新任一资产即刷新全局时间戳，可能让"其余资产全是陈旧价"时仍可铸造。改成 per-asset 后，按需推送（用户的 mint/burn 交易自带价格更新）才安全。
3. **真·批量更新 op**：`SignedPriceUpdateN` 是 **N 个签名**变体（一个资产），**不是**多资产批量。可加 `SignedPriceUpdateMulti`（一次消息带 index→price 字典）把 14 条消息压成 1 条。
