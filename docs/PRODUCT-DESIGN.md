## 1. 愿景与不可动摇的红线

- **愿景**：把一篮子全球大宗商品的真实购买力，做成**可编程的链上指数**，让被传统市场挡在外面的
  人也能持有"一篮子全球商品购买力"。
- **红线（不变）**：
  1. 当前是**合成指数代币 PLT**，**不是 1:1 实物储备的稳定币**，必须处处区分版本。
  2. 不碰链下期货自营；不早期冲 CEX；不刷量；不伪造喂价。
  3. 所有对外材料禁止"足额抵押/无风险锚定"话术。

## 4. 机制如何协同（主流程）

- **铸造**：用户存 USDC → Core 按 PPI 铸 PLT（经 minter；PLT 供应以 minter 为准）。
- **PPI 更新**：CAM（或直接 oracle）推**单资产标准化数据** → Core `computePpi` 链上重算。
- **赎回**：用户钱包 `AskToBurn` → minter 减供应 → 镜像回 Core 同步记账（已实现）。
- **市场**：DL-AMM 把 LP 流动性**压在 PPI 目标 tick**；偏离 PPI 时套利 + 稳定债券把价格拉回。
- **再平衡**：RTRA 的 `ΔA_i` **优先经离散池**分批成交降滑点。
- **风控联动**：CAM 的 `volatility/liquidity/riskState` → 动态调 DL-AMM 的 tick 宽度/激励区间/OneSide。

## 6. 架构如何更稳妥（**核心结论，先想清楚再动手**）

### 6.1 信任边界与故障隔离
- **CAM 隔离**是正确方向：坏 CAM 只能改**自己 index** 的快照，逐资产定点计算 + 范围校验 → 不污染全局。
- **市场层与核心解耦**：DL-AMM 故障**不应**能改核心记账；核心只承认 `minter`/已登记 oracle/CAM 的消息。
- **最小权限**：核心 owner 权限点（暂停/设 minter/设 oracle/CAM/篮子）未来收敛到**多签 + 时间锁**。

### 6.2 复杂度与自研风险（最重要的警告）
- **DL-AMM + 限价单 + 可编程激励 = 自研金融基础设施**，数月工程量 + 高强度审计，且**安全极难**。
- 对当前阶段（PoC、无真实流动性、无审计预算）：**自研 DL-AMM 的收益 < 风险**。
- **更稳妥的替代**：先接**现成 DEX** 建 PLT/USDC 池验证需求；DL-AMM 仅在需求确立、有审计资源后再上。

### 6.3 渐进路线（可回退）
1. 核心稳定 → 2. CAM（隔离数据）→ 3. **现成 DEX** 市场 → 4. 最小 DL-AMM（研究/测试网）→
5. 区间激励/OneSide/债券 → 6. RWA 储备。**每步独立、可回退，未过审不上主网。**

### 6.4 安全与治理
- 全链路：**多签 + 时间锁 + 全局暂停 + 单笔/窗口限额**（限额已在 Solana 版设计，TON 侧待补）。
- 变更可追溯；参数变更事件化；关键升级走时间锁。
- 第三方审计（Halborn）+ 形式化验证（Certora）+ 漏洞赏金。

### 6.5 经济安全
- **预言机操纵**：多源（RedStone+DIA）、时间戳单调（已做）、范围校验、`frozen` 熔断。
- **LP 激励被刷**：只奖励有效区间（TWAL + 有效性快照 + 边缘限流）。
- **挤兑/脱锚**：稳定债券 + 风险基金 + 分级暂停；**但合成版无实物兜底，仍需显著风险披露**。

### 6.6 合规底线
- 合成指数衍生品 vs 金融产品（需牌照）的界限，**不得混淆**；开真实铸赎前不做任何锚定承诺。

### 6.7 建议决策
- **现在做**：核心打磨（已做）、CAM 设计→Phase A（MockCam，纯代码可验证）、现成 DEX 集成调研。
- **现在不做**：自研 DL-AMM 上主网、真实储备铸赎、任何稳定币话术。
- **触发条件**：有真实需求 + 审计预算 + 合规路径后，再推进 L3/L4/L0。
