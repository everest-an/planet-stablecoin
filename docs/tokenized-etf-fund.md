# 目标产品：代币化 ETF 篮子基金（Tokenized ETF Fund）

> 你的原话：*"客户买我们的代币，我们帮他自动买入各类 ETF，赚个手续费；如果真涨了，客户真的赚钱。"*
> **这不再是"合成稳定币"，而是一个"代币化指数基金"。** 这是**成立**的（真资产、真分成）——
> 前提是你愿意承担**基金牌照 + 托管 + 合规**。下面把它讲清楚：怎么运转、代码怎么改、硬门槛在哪。

---

## 1. 一句话模型

**PLT = 基金份额。** 客户的钱 → 我们（运营方）通过券商**真实买入一篮子 ETF** → 资产进托管 →
PLT 按 **NAV（每份净值）** 定价 → 我们收**管理费/申购赎回费** → 篮子涨，客户真赚。

这等价于：**一支链上登记份额、可 7×24 申购赎回的指数基金**（类似 tokenized ETF / fund share）。

## 2. 谁赚钱、怎么赚

| 角色 | 赚什么 | 成立性 |
|---|---|---|
| **客户** | 篮子 ETF 的**资本利得**（真涨真赚）+ 分红转投 | ✅ 只要 ETF 真有、真涨 |
| **我们（运营方）** | **管理费**（AUM × 年费率，如 0.5–2%）+ **申购/赎回价差**（如 0.1–0.5%）+ 再平衡交易返佣 | ✅ 基金标准商业模式 |
| 风险 | 篮子会跌（客户亏）；托管/操作/合规风险 | ⚠️ 要如实披露 |

> 关键：**我们赚的是"费"，不是"赌方向"**——这是可持续的基金经济，比"稳定币套利"现实得多。

## 3. 目标架构

### 链上（TON，可复用现有大部分）
```
User ──USDC/TON──► Fund(Vault) ──► PLT shares (TEP-74)
                     │  NAV (链上)
                     │  supply / fee accrual / KYC allow-list
                     ▼
              Custodian attestation (签名: 持仓价值 + 份额)  ← M-of-N
```
- **PLT**：TEP-74 份额（**已有**）。
- **Fund 合约**：`NAV`、`totalSupply`、`申购/赎回`、`管理费计提`、可选 `KYC 白名单`。
- **申购（修 EC1）**：客户入金 → **托管方确认已买入 ETF（多签/attestation）** → 才按 NAV 铸份额。
  → **不能再凭消息体字段铸币**（那是当前唯一"被盗级"问题）。
- **赎回**：烧份额 → 平台卖出对应 ETF → 付客户（两阶段）。
- **NAV 预言机**：托管方/券商签"持仓价值"；沿用现有 **签名 + M-of-N + 时间戳单调** 设施（**已有**）。

### 链下（运营方，必须自建/外包）
- **券商 + 托管账户**：真正按目标权重买/卖 ETF。
- **再平衡**：权重漂移时调仓（可带阈值，现有 `shouldRebalance` 思路可复用）。
- **储备证明 / 审计**：定期 attestation（最好第三方），链上可验。
- **KYC/AML + 法币出入金**。
- **合规**：基金注册/牌照、募集说明书、托管协议、辖区选择。

### 法律（**最硬的门槛**，非代码）
- 在多数辖区，**PLT 就是"基金份额/证券"** → 需要**基金牌照 + 募集说明书 + 合规**。
- 这是"能不能做"的决定性因素；**技术不是难点**。

## 4. 现有代码：留 / 改 / 弃

| 组件 | 处置 |
|---|---|
| PLT TEP-74（minter+wallet） | ✅ **留**（就是份额） |
| `owner + SetOwner + PlanetTimelock` | ✅ **留**（基金治理） |
| 签名/M-of-N/时间戳单调预言机 | ✅ **留**（改指向"NAV/持仓 attestation"） |
| `Mint`/`BurnMirror` 记账 | 🔧 **改**：铸币**必须**以"真实入金 + 托管确认"为前提（修 EC1） |
| 商品 PPI（`computePpi`） | 🔧 **降级**为"展示用指数"（或去掉）；**份额价值 = ETF 的 NAV**，不是商品价 |
| 商品稳定性机制（分档费/债券/风险基金） | 🔧 **改语义**：费率改为"管理费 + 申赎价差"，不再是"稳定锚定费" |
| 测试/CI/安全审计/覆盖率 | ✅ **留**（工程质量直接迁移） |

## 5. 与"现在的合成币"的本质区别

| | 现在（合成指数币） | 目标（代币化 ETF 基金） |
|---|---|---|
| 资产 | ❌ 无 | ✅ 真 ETF（托管） |
| 客户为何赚钱 | ❌ 说不清（无市场/无兑付） | ✅ 篮子涨就赚（真资产） |
| 我们赚什么 | ❌ 费用桶"空转" | ✅ 管理费/价差（真现金流） |
| 硬门槛 | 无（因为这本来就不成立） | **牌照 + 托管 + 合规** |

## 6. 落地步骤（务实顺序）

1. **定位改口**（今天可做）：官网/白皮书/App 从"稳定币"改为"**代币化指数基金（PoC）**"——已开始做（PoC 声明 + 中性文案）。
2. **链上改造**（周级）：`Fund` 合约：NAV + 收费 + **入金驱动、托管确认**的申购/赎回（修 EC1）；复用现有 TEP-74/预言机/治理。
3. **链下打通**（月级）：券商/托管账户 + 自动买入 + 再平衡 + PoR。
4. **合规**（并行，决定性）：基金牌照 + 募集说明书 + KYC/AML。
5. **审计 + 上线**：第三方审计 → 小额试点 → 放量。

## 7. 老实结论

- ✅ **你的想法成立**：它是**基金**，不是"空转的合成币"；客户真赚、我们真收费——**只要 ETF 真买真托管**。
- 🔧 **代码要改的不多**（主要是"入金背书 + NAV + 收费"），**难的是牌照/托管/合规**。
- ⚠️ **红线不变**：在"真资产 + 合规"落地前，**只能是 PoC 展示**，不能对外募资/发行——否则就是**无牌的基金**，法律风险最高。
- 📌 **我的建议**：把这个方向写进白皮书 v2，作为**主线产品**；把"合成稳定币"降为历史 PoC。**先解决"能不能合规地做基金"，再谈技术。**
