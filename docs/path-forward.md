## 1. 路线 A —— 真 1:1 商品储备

**架构**：`custodian ⇄ reserve attestation ⇄ PlanetCore`；PLT 铸造 = 托管方确认收到资产 → Core 记账；赎回 = Core 指令 → 托管方交付。

- **链上**：`ReserveManager`（托管方签名/多签）、`Mint` 需**托管确认**（不能凭 body 字段）、`Redeem` 出金流程、`kyc` 白名单（若需要）。
- **链下/外部**：托管协议、**储备证明**（定期 attestation，链上可验）、法务/牌照（证券/商品属性）、审计。
- **要修的现状问题**：`EC1`（无背书铸造）、`burn` 兑付、托管对接。
- **代价/风险**：**最高**（时间、钱、监管）；一旦成立，是最强的产品。

## 2. 路线 B —— 超额抵押合成

**架构**：用户锁抵押（TON/USDC）→ 按预言机价铸 PLT（敞口）；抵押率 < 阈值 → 清算。

- **链上**：`Vault`（锁仓/铸/还/清算）、**清算拍卖**、**动态费率**、**预言机（含延迟/操纵防护）**、债务上限。
- **外部**：可信预言机、审计；无需托管/牌照（但仍有合规问题）。
- **要修的现状问题**：铸造逻辑整体替换（现为"凭空铸"）。
- **代价/风险**：**中高**；资本效率与清算安全是难点。

## 3. 路线 C —— 指数 / 积分代币（推荐先做）

**架构**：保持现有合约，但**去掉"稳定币/兑付"暗示**，明确为"**链上商品指数 + 社区积分/奖励**"。

- **链上**：**小改**——文案/命名去承诺；可选：把"reserve/burn 赎回"降级为"仅展示"，或干脆关闭铸造（改为积分发放）。
- **前端/官网**：**明示**"指数追踪 / PoC / 无背书、无兑付、无市场价"（现有 README/白皮书已声明，需在 App/官网**更醒目**）。
- **外部**：无。
- **代价/风险**：**最低**；风险主要是"别把它当稳定币宣传"。

---

## 4. 推荐路径（务实）

1. **立刻**：走 **C**（去承诺 + 明示）——**可以安全地展示/传播**，不会被误解为可兑付资产。
2. **并行**：把**技术资产做扎实**（合约审计、覆盖率、多签+时间锁、多源预言机 M-of-N）——这些对 A/B/C 都通用。
3. **择机**：若要真经济 → 评估 **A（有牌照/托管资源时）** 或 **B（有工程/风控能力时）**。
