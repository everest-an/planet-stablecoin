# 设计：PLTG 分配/归属 + 绑定式治理

> **状态**：设计（Design）。**未实现** —— 实现属于"下一版合约"，与审计结论一起部署（见 `docs/adr/0001-immutable-core-upgradeable-oracle-adapter.md`）。
> **动机**：v1 白皮书承诺了 PLTG DAO（§9.1 of the whitepaper），今天只落地了**经济层**（质押 + 分红 + 咨询投票）；**决策层缺失**，且 **1e9 的分配/归属从未执行**。
> **关联**：`docs/audit-prep.md`（不变量/信任模型）、`docs/whitepaper`（§9）、`docs/deploy-runbook.md`。

---

## 0. 目的

给出 PLTG（1e9 固定）**可审计的分配与归属**，以及**绑定式但受宪法约束**的治理机制，使 DAO 能真正控制参数**而不**获得搬库/增发/改规则的能力。

---

## 1. 核心矛盾与三条设计原则

**矛盾**：协议要"信任代码"；绑定治理却把权力交给代币多数。

**原则**

1. **治理≠托管（Governance ≠ Custody）** —— 治理可以调**有界参数**，**永远不能**转移资金、任意增发、或改变核心规则。
2. **宪法写死在代码里** —— 因为核心不可变（ADR-0001），**规则本身不可被治理修改** ✓。治理只能在边界内移动。
3. **一切生效都要经过时间锁 + 退出窗口** —— 复用现有 `PlanetTimelock`（`Propose → delay → Execute`）。

> 一句话：**不是"51% 说了算"，而是"51% 能在宪法允许的格子里移动，且持有人有整整一个 delay 的时间退出"。**

---

## 2. 权力划分（宪法表）

这是本设计的核心。**左列是治理能碰的，右列是治理永远碰不到的。**

| 参数 / 权力 | 边界（写死在合约里） | 控制者 |
|---|---|---|
| 商品权重 `wᵢ` | `0 ≤ wᵢ ≤ 150000`，且 `Σwᵢ = 1e6` | **DAO** |
| 新增商品 | **仅追加**；`basePrice` 不可改；单类 ≤15% | **DAO** |
| 费率（基础/斜率/上限） | 落在 `[FEE_MIN, FEE_MAX]`（建议 0.1%–3%） | **DAO** |
| 偏离阈值 | `[±1%, ±15%]` | **DAO** |
| 单笔限额 | `[0, LIMIT_CAP]` | **DAO** |
| 费用**分配比例**（30/50/20/10） | **写死在代码**，改动需迁移 | 无人（不可变） |
| **oracle 签名者集合 / 门限** | — | **多签（owner），不是 DAO** |
| **暂停 / 紧急制动** | — | **多签（owner），不是 DAO** |
| 金库支出 | 需治理提案 + 时间锁 | **DAO（延迟生效）** |
| **改代码 / 升级** | — | **不可能**（ADR-0001） |

**为什么 oracle 签名者与紧急制动不给 DAO？** ✗
给 DAO = 多数可以**喂假价** ✗（等于无限增发/掏空）✗。**喂价权与“刹车权”必须与“参数权”分属不同主体** ✓ —— 这是本设计里最重要的一条分权。

## 3. PLTG 分配与归属

### 3.1 分配（沿用 v1 承诺，不改）

| 桶 | 比例 | 数量 | 归属 |
|---|---|---|---|
| 社区激励 | 40% | 400,000,000 | 5 年线性（TGE 起） |
| 协议金库 | 25% | 250,000,000 | **无归属**，但由**时间锁**持有 |
| 核心团队 | 15% | 150,000,000 | 2 年 cliff + 3 年线性，**可撤销** |
| 投资者 | 12% | 120,000,000 | 1 年 cliff + 2 年线性，**可撤销** |
| 公开销售 | 8% | 80,000,000 | TGE 解锁 —— ⚠️ **合规门槛，见 §8** |

### 3.2 归属机制

新增 **`PlanetVesting`**（每桶一个实例，或一个实例多受益人以省 gas）：

```
vested(t) = A · clamp( (t − t₀ − c) / d , 0 , 1 )            (V1)
```
- `A` 总额、`t₀` 起始、`c` cliff、`d` 线性时长。
- **可撤销**（团队/投资者）：撤销时刻 `t_r`，受益人保留 `vested(t_r)`，**未归属部分退回金库** ✓。
- **领取制**（pull）：受益人在解锁曲线上任意时刻 `claim()` 已归属部分 ✓（避免推送成本）。

**关键规则：未归属的 PLTG 不能投票** ✓✓
否则"未来的币"会主导今天的决策 ✗。**投票权 = 已归属且已质押** 的 PLTG ✓。
（`PlanetVesting` 需与 `PlanetGov` 对账：只有 `vested` 部分可被 stake ✓。）

### 3.3 从现状到目标（当前 1e9 全在部署钱包手里 ✗）

```
deployer wallet ──▶ PlanetVesting ×3（社区 / 团队 / 投资者）
                ──▶ 金库（owner = PlanetTimelock）
                ──▶ 公开销售（暂缓，合规前置）
```
一次性划拨；此后 `deployer` 不再持有任何 PLTG ✓。

## 4. 绑定式治理

### 4.1 合约分工（新增两个，复用两个）

| 合约 | 职责 | 状态 |
|---|---|---|
| `PlanetGov` | **经济层**：质押 / 提现 / pro-rata 分红 / 投票记录 | 已有（本设计沿用） |
| **`PlanetGovernor`** | **决策层**：提案 / 投票期 / 法定人数 / 排队 | **新增** |
| **`PlanetGovernanceExecutor`** | **宪法执行器**：白名单 + 参数边界校验，然后向时间锁 `Propose` | **新增** |
| `PlanetTimelock` | `Propose → delay → Execute` | 已有，需支持**授权提案者** |

### 4.2 提案生命周期

```
propose       需持 ≥1% 已质押（GV-3 已实现 ✓）
  ↓           （建议：加少量 PLTG 保证金，防垃圾提案）
voting        5 天（生产）/ 短周期（测试网）
  ↓           quorum ≥ q·votable，且 for > against
queue         通过 → 交给 Executor
  ↓           Executor 校验：目标在白名单 ∧ 参数在边界内   ← ★ 宪法闸门
timelock      48h（生产建议 48h–7d）
  ↓           ← 持有人退出窗口
execute       时间锁 Execute → 目标合约生效
```

### 4.3 宪法闸门（Executor 的白名单）

Executor **不接受任意调用** ✗，只接受**枚举的消息类型 + 数值区间** ✓：

```
allow(SetWeight)        ⇔  0 ≤ wᵢ ≤ 150000  ∧  Σwᵢ = 1e6
allow(AddAsset)         ⇔  追加位 ∧ basePrice>0 ∧ 新权重使 Σ=1e6
allow(SetFeeParams)     ⇔  FEE_MIN ≤ base ≤ FEE_MAX ∧ slope ≤ SLOPE_MAX
allow(SetThresholds)    ⇔  |θ| ∈ [1%, 15%]
allow(SetLimits)        ⇔  0 ≤ maxPerTx ≤ LIMIT_CAP
reject(SetSigner|SetThreshold|SetPaused|SetOwner|SetJettonMinter|…)
```
> 即使**100% 的 PLTG** 投赞成，也**无法**改喂价、暂停、换 owner、改费率分配、或升级代码 ✓✓。
> 这条"拒绝清单"就是"治理≠托管"的可执行定义 ✓。

### 4.4 参数（建议值）

| 参数 | 建议 | 理由 |
|---|---|---|
| 提案门槛 | 1% 已质押（已实现 ✓） | 抗垃圾 |
| 法定人数 `q` | 4% 可投票量 | 冷启动不宜过高 |
| 通过 | `for > against` 且 `参与 ≥ q` | 简洁 |
| 结构性提案（新增商品/改费率区间） | `for ≥ 2/3 参与量` | 提高门槛 |
| 投票期 | 5 天 | 与时间锁错开 |
| 时间锁 delay（治理） | **48h**（生产） | 退出窗口 |
| 保证金 | 提议者 0.1% 已质押，通过即退 | 抗垃圾 + 无成本参与 |

### 4.5 紧急制动与安全委员会（中央化权衡，须披露）

- **多签可 `pause`** ✓（已有）—— 但**不能**用来完成 DAO 拒绝的事 ✗（`pause` 只能停、不能改参数 ✓，且不可绕过时间锁 ✓）。
- **可选：安全委员会否决权** —— 2/3 委员会可在提案生效前否决，**带日落条款**（如 12 个月后自动失效，或 TVL 超阈值后失效）✓。
  - 这是**权衡** ✗：它引入了中央化 ✓。**收益**：在冷启动期防灾难 ✓。**代价**：与"可信中立"叙事有张力 ✗。
  - 建议：**明确披露 + 写死日落** ✓，并把它列入宪法表让审计师评估 ✓。

## 5. 分阶段落地（不能一步到位）

| 阶段 | 内容 | 需要改什么 | 退出条件 |
|---|---|---|---|
| **S0（现在）** | 咨询投票：只记录结果 | 无 | — |
| **S1** | 划拨 PLTG：归属合约 + 时间锁金库；**投票权=已归属且已质押** | `PlanetVesting`（新） | 分配完成、可投票量可见 |

> 每阶段 = 一次重新部署（合约不可变）；建好后按 `docs/deploy-runbook.md` 执行 ✓。

## 6. 需要改动的合约清单

| 改动 | 类型 | 备注 |
|---|---|---|
| `PlanetVesting` | **新增** | 线性+cliff、可撤销、领取制 |
| `PlanetGovernor` | **新增** | 提案/投票/法定人数/排队 |
| `PlanetGovernanceExecutor` | **新增** | 白名单 + 边界（§4.3）|
| `PlanetTimelock` | 修改 | 支持"授权提案者"（否则只有 owner 能提议）|
| `PlanetGov` | 修改 | 投票权只认**已归属**质押（与 Vesting 对账）|
| 数值边界常量 | 修改 | `FEE_MIN/FEE_MAX`、`LIMIT_CAP` 等写入宪法 |
| 与 §4.3 拒绝清单相关 | **不改** | 保持 owner(多签) 控制 |

**不新增**：升级通道（ADR-0001 禁止）✓。

## 7. 失败模式与缓解

| 失败模式 | 缓解 |
|---|---|
| 51% 治理攻击 | §4.3 白名单 + 拒绝清单 + 宪法不可变 + delay 退出窗口 |
| 治理被"未来的币"主导 | 未归属不可投票（§3.2）|
| 投票参与率过低 | quorum + 分阶段（S0–S2）+ 委员会过渡（带日落）|
| 投票买卖 / 闪电贷治理 | 投票权=**已质押**（需先经历质押流程），提案保证金；可选时间加权 |
| 垃圾提案 | 1% 门槛（已实现）+ 保证金 |
| owner 多签被盗 | 时间锁 delay（生产 48h+）、多签 2/3+、暂停不能改参数 |
| 喂价被治理劫持 | **喂价权不在 DAO**（§2）|
| 归属合约被绕过投票 | Vesting→Gov 对账，未归属不可质押 |

## 8. 待你（或律师）决定的事项

1. **公开销售 8%** —— 触发**证券/牌照**问题；本设计**不提供**链上公开销售机制，建议在合规意见后再定。
2. **管辖区与主体** —— 金库/基金会的实体形式，决定税务与披露。
3. **委员会**：要不要？给谁？日落多长？（中央化权衡）
4. **法定人数/投票期**建议值是否接受（4% / 5 天）。
5. **是否引入时间加权投票（ve-lock）** —— 更强抗攻击，但复杂度与理解成本更高。
6. **费率上限 `FEE_MAX`** 定多少（建议 3%）。

---

## 9. 审计师会重点攻击

1. Executor 的白名单能否被**构造输入绕过**（编码歧义、可升级目标、别名地址）？
2. 时间锁的"授权提案者"是否会**削弱**原 owner 的约束？
3. `PlanetVesting` ⇄ `PlanetGov` 的**归属对账**是否存在可被利用的时间差（先质押后撤销）？
4. 法定人数/投票权的**快照点**在哪？能否用闪电贷/在快照后转移来双花投票权？
5. 撤销归属时，`vested(t_r)` 的计算与 `claim` 是否会**双付**？
6. **拒绝清单**是否真的覆盖了所有"改变托管/规则"的消息（含新增消息类型的默认拒绝）？
