## 2. ⚠️ Telegram 入口的公链限制（决定性事实）

### 2.1 Telegram 官方《Blockchain Guidelines》要点
Mini App 集成区块链必须满足（<https://core.telegram.org/bots/blockchain-guidelines>）：

1. **只能用 TON 链**创建 / 分发代币或链上资产；
2. **只能通过 TON Connect SDK** 连接钱包；
3. **不得推广非 TON 钱包**。

> 原文要点：「Tokens and NFTs on other blockchains like Ethereum and BNB are **not permitted**」；存量非 TON Mini App 须在 **2025-02-21** 前迁移；2025-01-21 后新发资产立即适用。
> 适用范围：**Mini App 及其 Bot**；不含 Mini App 组件的普通 Bot 豁免。

### 2.2 结论
**只要「TG 第一入口」里要连钱包 / 签名 / 买卖（链上操作），链就被锁死为 TON。**
EVM / Solana / BSC 在 Telegram Mini App 内做链上操作 = **违规**。

**三个缝隙（可利用）**
- 规则针对 Mini App **自身的链上功能**；Telegram Apps Center 目录**本身接受其他链的 app**。
- 小程序若只「看行情 / 跳转」，不做链上操作 → 风险低。
- 技术上可用**内嵌钱包**（Privy / Reown AppKit / TMA Wallet MPC）在 TG 内跑 EVM/Solana → **能跑，但违反政策**，随时可能被限制/下架。
- 注意：WalletConnect 在 TG 的 iframe 内有**已知兼容问题**（常卡死），内嵌钱包（Privy）体验更稳。

### 2.3 四个架构选择

| 方案 | 做法 | 合规 | 体验 | 代价 |
|---|---|---|---|---|
| **A. 全 TON** | 协议重写至 TON，TON Connect | ✅ | ✅ 1 键无感 | 现有 Solana/Rust 代码重写（Tact/FunC）；TON DeFi/指数生态最薄 |
| **B. TG 外壳 + 内嵌钱包** | Mini App 用 Privy/Reown 连 BSC/Solana | ❌ 违规 | ✅ | **平台封禁风险** |
| **C. TG 只做社区 + 看板** | 小程序展示/任务/空投，交易跳站外 Web App | ✅ | ⚠️ 转化打折 | 流失一层 |
| **D. 双轨** | TON 做积分/品牌代币，主协议在 BSC | ⚠️ 灰 | ⚠️ | 跨链复杂 |

**推荐**
- **长期做正 → A（协议上 TON）**：TG 10 亿用户 + 内嵌钱包 + 已原生 USDT 与 **Tether Gold (XAUt)**；TON 在俄罗斯/中东/东南亚/非洲的「被挡住的人」密度最高。
- **快速冷启动、接受风险 → B**（Privy 内嵌钱包跑 BSC），需备好被封的 Plan B。
- **最稳 → C**（TG 做获客外壳，交易在站外 Web App）。

> **待拍板**：见 §7。

## 4. 分阶段冷启动路线

### Phase 0｜TG 入口 MVP
- 交付：Telegram Mini App，三步完成「看指数 → 了解一篮子 → 买入 PLT」。
- 多语言：英/中/西/土耳其/印尼/越南/俄。
- 不托管资金：纯合约交互（守住「无主体」）。

### Phase 1｜公平发射 + 点数/空投
- 无预售、无 VC；LP 锁仓或销毁。
- 点数：邀请 + 持仓 + 提供 LP + 社交任务 → 早期空投。
- 主场按 §2 决策：A=TON 发射；B/C=BSC(Pancake) 发射 + TG 外壳。

### Phase 2｜造「用途」+ 留存（关键）
- LP 挖矿；接入借贷协议当非相关抵押品。
- **把 LP/协议手续费收益分给持有者**（合约分红，无主体也能做）。
- 没有收益 = 纯投机 → 用户为积分来、积分走（Ethena 教训：$7.5 亿激励，USDe 从 $150 亿 → <$50 亿）。

### Phase 3｜流动性/交易层
- 上 Hyperliquid：花 HYPE 拍 HIP-1 上现货订单簿 + 挂永续，吃交易费（部署者可拿最高 100% 交易费）。
- 视规模再考虑是否需要轻主体对接 CEX。

## 6. 风险与红线

**三条红线**
1. **不碰用户的钱**（不托管、不代收）——守住「无主体」。
2. **不承诺赎回实物/收益/锚定**，一律说「合成指数 / 抗通胀篮子」。
3. **geo-block 美国及受限地区**。

**风险**
- Telegram 封禁（B 方案）→ 备 C 方案。
- TON 生态薄（A 方案）→ 需要自建做市/流动性。
- 纯激励获客不可持续 → 必须 Phase 2 上真实收益。
- 匿名 ≠ 免责：募资/托管/承诺收益会触发监管，务必守住三红线。

## 7. 多链扩展策略（何时 / 如何）

> 结论：**不要同步发多链。先单链（TON）做到 PMF，再「枢纽-辐条」扩展。**

**为什么不建议同步多链（早期）**
1. **流动性碎片化**：预算分散到多个池，每条链都上不了榜/深度不够（OpenLiquid：同时发两链能 double 曝光，但分流会削弱每条链各自的 trending 潜力）。
2. **桥 = 头号被黑目标**：多链要靠跨链桥；匿名小团队自建/运营桥风险极高。
3. **TG 规则反噬**：Telegram 禁止推广非 TON 资产 → TG 入口只能推 TON，多链版本推不进去，获客闭环断裂。
4. **运维爆炸**：无主体 + 无预算，多链 = 多份合约/预言机/流动性/社区/攻击面。
5. **供应纪律**：多链必须定「canonical 主链 + 桥」，供应对账出错即漏洞。

**正确节奏（枢纽-辐条）**
| 阶段 | 链 | 做法 |
|---|---|---|
| Phase 1（现在） | **TON only** | 单链、单池做深，TG 入口闭环 |
| Phase 2（有 PMF 后） | TON（枢纽）+ BSC（首选第二链） | 主供应（canonical）留 TON，用**成熟桥**（LayerZero/Wormhole）镜像到 BSC |
| Phase 3 | + Solana / Base | 全链分发（对标 Ondo USDY 11 链的渐进路线） |

**若坚持早期跨链**：对「合成指数」（无实物储备）可做**各链独立发行**（不走桥，每链自算 PPI）——规避桥风险，但供应碎片化、每链需各自预言机（Pyth/Chainlink/TON oracle），一致性是新风险。**仍不推荐早期做。**

**扩链触发条件**：单链有稳定流动性 + 真实留存用户（非纯激励）+ 有可信桥方案 —— 三者齐备再扩。
