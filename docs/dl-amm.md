# Planet × DL-AMM —— 离散流动性二级市场设计稿

> 状态：**设计稿（未实现）**。DL-AMM 是重大自研系统，实施成本与安全风险极高，务必先读
> `docs/PRODUCT-DESIGN.md` §6（架构稳健性）再决定是否自研。
> 关联：`docs/commodity-cam.md`（CAM）、`docs/ppi-multiasset.md`（PPI）、`docs/PRD.md`。

## 0. 定位

DL-AMM（Discrete-Liquidity AMM）= PLT 的**二级市场层**：用**离散 tick + 常数和（在目标区间）**的
做市模型，把流动性**集中在 PPI 目标附近**，并**内置 tick 限价单**，使二级市场成为
**系统稳定机制的一部分**，弥补铸造‑赎回的反应延迟。

> ⚠️ 它只解决**交易层**；大宗商品底层风险仍靠**储备 + CAM + 风险基金**兜底。

## 1. 为什么不是普通 CPMM

| 维度 | 普通 CPMM（x·y=k） | DL-AMM（本设计） |
|---|---|---|
| 流动性分布 | 全区间均匀（远离现价浪费） | **集中在 PPI 目标 tick 附近**（资本效率高） |
| 稳定币式资产 | 滑点大、易脱锚 | 目标区间用**常数和**→ 深度大、贴近 1:1 |
| 限价单 | 无（靠外部协议） | **内置 tick 限价单** |
| 激励 | 全局 LP 分润 | **只奖励有效区间 LP**（LiquidBox 式） |
| 与 PPI 协同 | 无 | **CAM 输入 → 动态调 tick 宽度/激励区间；跳变切 OneSide** |

## 2. 核心模型

### 2.1 离散 tick
- 价格轴按固定步长（如 `tickSize = 0.1%`）离散为 tick；记 PPI 目标所在 tick 为 `tick*`。
- 每个 tick 区间 `[p_i, p_{i+1})` 存 LP 的**区间流动性**。
- 交易在 tick 间"跳跃"结算，便于**精确控制有效区间**与**逐 tick 激励**。

### 2.2 目标区间用常数和
- 在 `tick*` 附近 `±k` 个 tick 内，做市函数用**常数和** `x + y = C`（贴合 ≈1:1 的稳定资产，深度最大化、几乎零滑点）。
- 超出目标区间，边界保护：**限制单边耗尽**（见 §2.4 OneSide）或退化到常数积以提供连续性。

### 2.3 集中流动性
- LP 指定 `[lower, upper]` tick 区间提供流动性；只有区间**覆盖当前 tick** 时才"有效"（earning）。
- 目标：**默认把流动性压在 PPI 目标附近**，远离目标不激励。

### 2.4 OneSide 单边模式（PPI 大幅跳变时）
- 当 CAM 报 `|ΔPPI|` 超阈值，池子**自动切 OneSide**：只允许沿**回归 PPI** 方向的单边流动性，
  防止区间被单向套利"打穿"后 LP 全部被剃头。
- 跳变恢复（回到 `±k` 内）后切回双边常数和模式。

## 3. 与 CAM 协同（动态区间）

CAM（见 `docs/commodity-cam.md`）标准输出 `price/volatility/liquidity/riskState`。映射到池子参数：

| CAM 输出 | DL-AMM 响应 |
|---|---|
| `PPI`（由 price 聚合） | 决定 **`tick*`（激励中心）** |
| `volatility` 高 | **加宽 tick 宽度 / 激励区间**（给波动留缓冲，减少被套利） |
| `liquidity` 低 | 提高激励权重（吸引该区间补流动性） |
| `riskState=frozen` | 该资产相关池子**暂停激励**；必要时暂停新增流动性 |
| PPI 大幅跳变 | **切 OneSide**（§2.4） |

## 4. LiquidBox 式可编程挖矿（只奖励有效区间）

- **计酬规则**：`reward_lp = Σ_over_epoch ( effective_liquidity_lp / total_effective_liquidity ) · emission`，
  其中**仅当 LP 区间覆盖当前 tick 时计为 effective**。
- **抗刷**：时间加权（TWAL）；区间有效性快照；对"1 tick 边缘反复进出"限流；emission 由 PLTG/手续费供给，不由融资。
- **目的**：把激励精准投向**维持 PPI 附近深度**的 LP，而非全局撒币。

## 5. 稳定工具（复用 tick 限价单）

1. **链上套利入口**：tick 限价单本身就是"价格偏离 PPI 就有人吃单"的入口——市价 > PPI，套利者卖 PLT 压低；
   市价 < PPI，套利者买 PLT 抬升。**把外部套利者变成稳定机制的执行者**。
2. **稳定债券（Stabilization Bond）**：当 `PPI < 0.95`（白皮书阈值），协议**折价发行债券**（以未来手续费/储备偿还），
   吸收抛压、回收 PLT，缓冲下行。复用 tick 限价撮合其一级认购。

## 6. 储备再平衡路由

- 链上合成资产的**调仓**（RTRA 计算的 `ΔA_i`）**优先路由到离散流动性池**，分批逐 tick 成交，**降低滑点**。
- 仅当池子深度不足时，才回退到其它路径（未来真实储备/RWA 渠道）。

## 7. 明确未实现 + 依赖

- **当前无任何 DL-AMM 代码**。本稿是机制设计。
- 依赖：核心（`PlanetCore`）✅、CAM（设计稿）、LP/激励代币经济（PLTG，未发）、审计。
- **规模警告**：自研 AMM + 限价单 + 可编程激励 = 数月工程量 + 高强度审计；**不建议在核心未稳、无真实需求前自研**（见 PRODUCT-DESIGN §6）。

## 8. 分期（建议）

- **M0**：先接**现成 DEX**（TON 上已有）建 PLT/USDC 池，验证需求与价格行为。**不自研。**
- **M1**：最小 DL-AMM（常数和 + 少量 tick + 集中流动性），仅供研究与内部测试。
- **M2**：LiquidBox 式区间激励 + 与 CAM 的动态参数联动。
- **M3**：OneSide 模式 + 稳定债券 + 再平衡路由。
- 每期都需独立审计；**任一环节未过审不得上主网**。
