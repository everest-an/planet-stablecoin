执行摘要

永续市场用价格清算仓位；当价格来自单一来源时，清算引擎无法区分「真实波动」与「坏数据」，两者都会被当成真实价格执行。Planet 的出发点不是再做一个价格源，而是让价格附带自身的数据质量。

指数由 14 种商品加权构成，1.0 为期初值。每个资产随价格一起发布风险状态：正常、警戒、冻结。冻结资产从指数中剔除并按活跃权重归一；冻结权重上限 40%。主网写路径为 2-of-3 签名的拉取式预言机，单钥 relayer 路径锁定为 address(0)。

在指数之上是一个永续市场：LP 池为对手盘，最高 3x 杠杆、10% 维持保证金、持仓上限为池子的 2 倍。清算要求仓位在现货价与 30 分钟快照均值两侧都击穿，单次坏价不足以触发强平。

读者可据此做出的三个决定

  • 是否把该指数用于结算参考（需接受：自审、无外部审计）。
  • 是否把风险状态接入自身保证金逻辑（接口见第 08 章）。
  • 是否作为 LP 提供对手盘资金（风险见第 07 章）。

01 · index & basket

指数与篮子

篮子包含 14 种商品，覆盖能源、贵金属与工业金属、农产品与工业原料。每个资产有四个关键字段：权重（ppm，单资产上限 15%）、期初基准价（锁定后不可改）、当前价、风险状态。权重总和必须等于 1,000,000 ppm，在每次价格更新时校验。

指数公式

PPI = Σ wᵢ · (pᵢ / bᵢ) / Σ wᵢ　（仅对非冻结资产求和；bᵢ 为期初基准价）

冻结资产同时从分子与分母剔除，因此指数在资产退场时保持连续，而不是被一个不再更新的价格拖住。冻结权重上限（40%）防止篮子被逐步收缩到单一商品。

图示为权重结构示意；真实权重以 PlanetCore 链上 assets(i) 读取为准。

指数不是稳定币

指数没有商品储备、没有赎回权。它是一个价格指数：1.0 是期初的相对值，1.01 表示篮子比期初贵 1%。PLT 代币在主网的铸造已禁用（depositToken = 0），因此本文件不把铸赎当作现有能力。

篮子构建规则

  • 权重以 ppm 表示，总和必须在每次价格更新时等于 1,000,000；构建期允许逐步添加，但任何一次推价前必须补齐。
  • 单资产权重上限 15%；期初基准价一旦锁定不可修改，当前价可更新。
  • 指数只对非冻结资产求和并按活跃权重归一，因此单个资产退场不会让指数跳空。

示例：资产 A 权重 30%、价格为期初 1.10；资产 B 权重 20%、价格 0.95；其余冻结 → PPI = (0.30×1.10 + 0.20×0.95) / 0.50 = 1.040

02 · data quality

数据质量与存活门

数据质量不是注释，是合约字段。每个资产带 riskState，市场级判定由两个条件合成：全局最后更新时间与各资产状态。

级别触发场所侧含义
正常所有资产正常且最后更新 ≤ 30 分钟可正常结算
警戒最后更新 > 30 分钟，或任一资产被标记警戒可用；建议提高保证金（永续中杠杆减半）
冻结最后更新 > 6 小时，或任一资产被冻结不开放新风险；结算使用最后已知价格

为什么用「最旧资产」而不是「最近更新」

全局时间戳只能说明「有人刚推过价」，不能说明「每个输入都新鲜」。所以铸赎的门槛取活跃资产中最旧的更新时间；一个新鲜的资产不能让十三个过期的输入看起来有效。

跳变与冻结的边界

  • 单次更新价格跳变不超过 50%，否则拒绝；超过时只能由 owner 通过 timelock 使用强制价路径，且强制价自动标记为警戒。
  • 冻结资产从指数剔除；冻结权重上限 40%，防止篮子被收缩为单一商品。
  • 永续在冻结状态下只允许「深度水下」仓位被清算（权益低于维持保证金的一半），避免用最后已知价格清算临界仓位。

验证链条

步骤检查失败结果
1 · 签名2-of-3 验签；域绑定 oracle 地址与 chainId载荷被拒绝
2 · 链上时间戳严格递增；跳变 ≤ 50%；权重和 = 1,000,000交易 revert
3 · 消费读取 oracleAgeSeconds 与各资产 riskState场所应阻断新风险或提高保证金

三步都在链上可复核；API 只是这三步的只读封装。

03 · oracle

预言机：2-of-3 拉取式

主网只有一条价格写路径：任意人提交一份由 3 个注册签名者中至少 2 个签名的载荷，合约验证后写入。单个密钥不能移动价格；单钥 relayer 路径在部署时被禁用并每日复核。

签名绑定了什么

digest = keccak256(DOMAIN, oracle地址, chainId, consumer, index, price, volatility, liquidity, riskState, timestamp)

因此签名不能跨链重放、不能跨合约重放、不能改字段重用。重放本身由 core 的严格递增时间戳挡住：任何时间戳不大于链上记录的载荷都会被拒绝。签名可锻性按 EIP-2 处理（s 超过曲线半阶即拒），同一签名者重复签名只计一次（位图）。

拉取式的代价：谁付钱

签名是免费的，上链不是。当前由运维每 5 小时提交一批（一个批次约覆盖 14 个资产），交易者在下单前也会自行提交所交易资产的新价（见第 08 章）。这解决了「公开签名喂价先于链上落账」的抢跑窗口，但也意味着：没有消费者时，运维就是消费者。

威胁模型

攻击防线
单钥改价主网 relayer 锁定为 0；价格源构造时拒绝启用 relayer 的 core
签名重放严格递增时间戳；载荷含 chainId 与 consumer

04 · perpetual market

永续市场与 LP 池

永续的对手盘是一个 USDC 池，而非订单簿。交易者的盈亏由池子承担与收取；平台只收开平仓费、协议分成与清算罚金的一半。合约中没有让 owner 随行情获利的路径。

参数值约束
最高杠杆3x警戒状态下减半
维持保证金10%维持 × 杠杆 < 100%²，杜绝开仓即爆
持仓上限2× 池子防止池子无法兑付
开/平仓费10 bps上限 100 bps
协议分成30%上限 50%；treasury 未设时全部归池
资金费keeper 设定合约上限 ±8%/天；运维规则按净敞口 ±50 bps/天

份额与提款

LP 存入 USDC 换取份额，份额价格随池子盈亏变化。提款受一条硬约束：提款后净持仓不得超过池子的 2 倍，否则拒绝——不允许 LP 在仓位未平时抽走对手盘资金。

现状：池子在上线时为 0，持仓上限为 0，任何开仓都会被拒绝。这是设计使然，不是故障。

资金费与激励

资金费按累计索引结算：开仓时记录索引，平仓时按差额乘名义值。费率由 keeper 在合约上限（±8%/天）内设定；运维规则按净敞口与池子比例推导，目标上限 ±50 bps/天。资金费不会回溯生效——每次设费率前先结算到当前时间。

这意味着资金费是「有界规则」，不是订单簿永续那种由 mark-index 溢价驱动的自我均衡机制。读者应把它当作运营参数而非市场信号。

05 · liquidation & bad debt

清算、TWAP 门与坏账路径

清算是最容易把「坏数据」变成「真实损失」的地方。Planet 的清算有三道门：

门一：双侧击穿（TWAP 门）

仓位必须在现货价与 30 分钟快照均值两侧都低于维持保证金才可强平；判定取对交易者更有利的一侧。单次坏价只会让仓位「看起来」水下，不会触发清算。快照环每 30 分钟最多记录一次，防止一次坏价后瞬间灌满环。

门二：冻结期只清算深度水下

当数据冻结（>6 小时或无消费者），只有权益低于维持保证金一半的仓位可被清算。临界仓位不会被最后已知价格清算。

门三：赔付封顶

当池子不足以支付赢家时，赔付按池子余额封顶并发出 PoolShortfall 事件——不 revert、不冻结所有交易者。代价由当次结算承担，而不是让系统整体卡死。

赏金：让「该清的仓位」真的被清

只有正权益的仓位才有清算动力，而坏账恰恰出现在权益为零或为负时。赏金取「抵押的 0.5%」与「剩余权益的一半」中的较大者，并封顶于抵押本身：水下仓位也有人愿意清。

已知边界：TWAP 保护会延后清算，延后期间的额外亏损由池子承担。这是「防坏价」与「防坏账」之间的显式取舍。

算例：3x 多单

名义 3,000；抵押 1,000；维持 10% → 维持额 300。
现货跌至 0.75 期初价：权益 = 1,000 − 750 = 250 < 300（现货侧击穿）
若 30 分钟均值仍为 0.80：TWAP 侧权益 = 400 ≥ 300 → 拒绝清算
均值回落至 0.76：TWAP 侧权益 = 280 < 300 → 执行清算，按现货价结算

该算例对应 twap-guardian 测试中的多空两侧用例，测试结果为 12/12 通过。

node guards-test.mjs · node fuzz-perp.mjs · node adversarial.mjs · node twap-guardian-test.mjs

自审中已修复的问题

  • 公开喂价抢跑（高）：签名喂价公开但每 5 小时才上链，读 API 者可锁定旧价开仓、新价平仓，从池子套利。修复：交易页面在下单前自行提交所交易资产的新价，entry 永远新鲜。
  • TWAP 快照无频率限制：一次坏价后连发 8 次快照可洗掉清算门。修复：快照最短间隔 30 分钟。
  • 预言机时间戳未来值：签名时间戳常领先链上时钟，直接相减会下溢并卡住开仓。修复：未来时间戳按年龄 0 处理。
  • 队列在宽限期后卡死：提案超过可执行窗口后只能人工恢复。修复：自动取消并重新提案。

仍未关闭的问题

  • 中timelock 的管理函数（改延迟/改主人）不经延迟即可由 EOA 调用。修复方案：自持 timelock（execute 公开 + 所有权移交），已排入队列。
  • 低抵押代币与代币地址在铸币后仍可更换——主网值已固定，属治理纪律问题。
  • 信息全暂停同时停止推价，永续随之进入只减仓。已记录为设计取舍。

07 · known limits

已知限制

以下不是待办清单，是读者做决定前应当接受的结构性事实。

1. LP 结构性做空指数。交易者净多头时，池子净空头。10% 的指数上涨在 2 倍持仓上限下会使池子承受约 20% 的损失；33% 的单边行情会带走约三分之二的池子资本。资金费与手续费是对该风险的补偿，不是消除。

2. 资金费是规则，不是市场机制。没有 mark-index 溢价可供推导；费率由 keeper 按净敞口规则设定（±50 bps/天，合约上限 ±8%/天）。它不会像订单簿永续那样自动均衡。

3. 没有外部审计。自审可复现，但不等于独立审计。任何以本指数结算真钱的场所，应把外部审计列为接入前置条件。

4. 指数是价格，不是资产。没有商品储备、没有赎回权；PLT 主网铸造已禁用。不要把 PPI 当作可赎回的商品凭证。

5. 数据存活依赖消费者。没有消费者就没有更新；没有更新就没有新风险。运维的 5 小时批次是当前的兜底，成本约每天数美元，余额不足会先告警再停摆。

LP 亏损情景（1,000,000 池子 · 持仓上限 2× 池子）

指数单边变动交易者净盈利池子结果
+10%200,000−20%
+20%400,000−40%
+33%660,000−66%

未计手续费与资金费；它们是对该敞口的补偿，量级远小于单边行情。清算会在仓位权益跌破维持保证金时截断进一步损失。

一次读取的完整示例

curl -s https://ppppp.space/api/v1/ppi | jq '{ppi, age: .oracleAgeSeconds, flags: [.assets[] | select(.riskState>0) | .symbol]}'

限流：读取 30 次/分钟，签名喂价 8 次/分钟；超限返回 429 与 Retry-After。API 只读、不持有资金、不要求 API key。

10 · architecture principles

架构原理

这套系统由四条边界组成：合约只做结算，API 只做只读封装，分发层不持有密钥，治理只有一条带延迟的路径。下面六条原则是设计时用来做取舍的，不是宣传语。

1. 结算与数据质量同源

风险状态与价格写在同一个合约的同一个结构里，而不是两个服务各自维护。消费方读一次 assets(i) 就同时拿到价格与状态，不存在「价格到了、状态没到」的时间差。

2. 单钥不可移价

主网只接受 2-of-3 签名载荷；单钥 relayer 路径被锁定为 address(0)，价格源在构造时拒绝启用 relayer 的 core。这把「信任一个运维」换成了「信任三个签名者中的两个」。

3. 会计不变量优先于功能

核心不变量是「合约余额 = 交易者抵押 + 池子资产」。每一次状态变更后都成立，并由 900 步随机测试逐步验证。任何新功能若破坏这条等式，直接否决。

4. 失败必须显式

池子付不出时发 PoolShortfall 而不是 revert；数据过期时进入只减仓而不是继续开仓；坏价来临前先降杠杆。系统的失败模式要能被监控和告警看见。

5. 治理有一条延迟路径

所有特权操作经 timelock：propose → 6h → execute。规划中的自持 timelock 会让管理函数本身也进入延迟，消除「持钥者可即时缩短延迟」的旁路。

6. 分发只读、无密钥

API、OpenAPI、MCP server 都是只读封装，不持有任何私钥，不在客户端存放签名能力。签名只发生在服务端的签名端点，且只能签价格，不能动资金。

层次之间只有单向依赖：下层不知道上层存在；分发层可以整体替换而不影响结算。

目标产品形态（规划）

本章描述的是目标，不是现状。当前只有指数与永续上线；代币层与贵金属层是规划中的能力，标注为「规划」，实现顺序见下一章。

三层结构

层目标能力状态
定价层PPI 指数：14 商品、风险状态、2-of-3 拉取式预言机已上线
代币层PLT：以 USDC 储备为抵押、按 PPI 铸赎的购买力代币规划
交易层指数永续（已上线）；贵金属市场（规划）部分上线

PLT：购买力代币，不是美元稳定币

目标是让 PLT 成为「一篮子商品的购买力份额」：铸造时按当前 PPI 收取 USDC 并发行 PLT；赎回时销毁 PLT 并按 PPI 支付 USDC。费率随指数偏离期初的幅度连续上升（0.5% 起，15% 偏离处拒绝铸赎），偏离越大越贵，抑制套利。储备、风险基金与质押的比例在合约中固定，不由运营临时决定。

重要限定：PLT 追踪的是商品购买力，不是美元。它没有 1:1 美元储备，也不承诺美元价格稳定。把它称作「稳定币」会误导用户，也会带来不必要的监管预期。

贵金属：两条路径，二选一

  • 路径 A（优先）：与发行方合作，接入已存在的代币化金属（PAXG / XAUT / VNXAU / KAU）。协议不发行、不托管，只做定价、路由与市场。
  • 路径 B（重资产）：自建 1:1 托管代币——需要托管方、审计、储备证明与司法辖区合规。规划中，未启动。

为什么先指数、后代币

代币层依赖指数先被独立验证：如果指数本身没有记录、没有消费者、没有审计，铸赎只是在给一个未经验证的数字加杠杆。因此顺序是：指数上线并被外部读取 → 永续被消费 → 代币层接线。贵金属市场同理，先有定价与风控，再谈发行或合作。

PLT 费率带（取自合约常量）

指数偏离期初铸赎费率
≤ 3%0.5%
3% → 15%连续上升至 3%
> 15%拒绝铸赎（band reject）

费率连续、无台阶：不存在「把指数推过某个边界就能改变所有人成本」的套利点。
