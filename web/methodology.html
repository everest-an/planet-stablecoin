Basket & index methodology

version 1.0 · reviewed October 2026 · this page is the rulebook, not marketing

Deployment. This rulebook governs the index live on Arbitrum One: core 0x61de052af7cb7dc957a07b1e6298152bb851cbbb, token 0xee270802969f0689e3085331d47679bdc5bf4512, timelock 0xa1fdb9f95210af1d968872f6fc86f623a3e3017c, oracle 0x0daf541ef7e41402070bc549f91475ab368d1824 — all verified on Arbiscan. The oracle is 2-of-3 and pull: prices are signed for free (/api/v1/price-signed) and whoever consumes one submits it and pays that gas. Minting is disabled: there is no deposit token, so no funds can enter. Live index: /ppi.

Why this page exists: a self-assembled commodity index is only as credible as its rulebook. If the basket were an undisclosed average of coin prices, the number would mean nothing. Everything below is the actual rule the contract enforces today (testnet), plus what is explicitly not claimed.

1. What the index is, and what it is not

The purchasing-power index (PPI) is a single number that tracks the price of a fixed basket of commodities, where 1.000000 is the index value on the base date. It is a measurement, computed on-chain from signed prices.

It is not a claim on any commodity. Minting pulls test USDC and redeeming pays it back from the reserve, but there is no commodity reserve behind it. There is no peg and no target. PLT is a synthetic token that expresses the index; it is not a stablecoin and this is not a yield product.

3. The two rules that make it trustworthy

  • Cap: no single commodity may exceed 15% (150 000 ppm). The contract rejects any add or re-weight above the cap, so no single market can dominate the index.
  • Sum: the weights of the active basket must equal exactly 100%. The oracle path verifies this on every update, so the index cannot be silently diluted.

4. Base prices are frozen

Each commodity has a base price recorded when the basket is configured. Once the basket is locked, base prices are immutable: the governance actions that change weights cannot touch them. This is deliberate — if base prices were editable, the owner could rewrite the index history.

5. The index formula

Over all active commodities:

PPI = Σ ( wᵢ · Pᵢ / Pᵦᵢ )  ÷  Σ wᵢ
  • wᵢ — the commodity's weight (ppm)
  • Pᵢ — its latest accepted price
  • Pᵦᵢ — its base price

With nothing frozen this is the plain weighted average of the price ratios. When a commodity is frozen (see §7) it is dropped from both sums, and the remaining weights are renormalised — so a single bad data source cannot pull the whole index. All arithmetic is 1e6 fixed point; there are no floats anywhere on-chain.

6. Where prices come from

An off-chain relayer reads up to four independent channels per commodity: Yahoo Finance is the primary, and Sina, Tencent and Eastmoney are confirmations only when they land within 0.5%. It is not a median — a 1% gap is usually a different contract expiry, and averaging two expiries blends two different assets. The live write path is an authorised relayer; the SignedPriceOracle ECDSA M-of-N path is deployed and its signer set is 2-of-3 on Arbitrum One today.

8. Update cadence

A scheduled run refreshes the feed hourly and pushes a commodity only when its price has moved more than 0.1% since the last on-chain value; a heartbeat forces a refresh before the six-hour mint guard. The on-chain index is recomputed on every price update.

9. How the basket changes

Governance has exactly three moves, and nothing else:

  • Add a commodity — appended at the next index; existing indices are never overwritten.
  • Re-weight an existing commodity — subject to the 15% cap. Base prices are untouched.
  • Retire a commodity — set its weight to 0. It stops contributing to the index without reordering anything (reordering is the dangerous operation this design avoids).

Because zeroing one weight breaks the 100% sum, a retirement must be paired with offsetting increases in the same batch; until the sum is restored, oracle updates fail loudly rather than producing a wrong index. On testnet the owner is a 60-second timelock, so every change is proposed, waits, then executes; production would use a multisig behind a longer delay, and the intent is a quarterly, rules-based re-weight.

10. What is explicitly not claimed

  • No commodity reserve and no redemption for commodities. Mints are collateralised by test USDC, which has no value; there is no collateral ratio promise.
  • No NAV, no yield, no peg and no promise to hold any particular value.
  • No third-party audit yet — this is unaudited proof-of-concept code on testnet.
  • No claim that the on-chain index equals any real tradable basket's return; it is a construction, and constructions have tracking differences.

11. Reproduce it yourself

Nothing here requires trusting this page. Read the chain directly:

  • ppi(), assetCount(), assetAt(i), baseLocked(), maxAssetWeight(), threshold() — the index and the basket.
  • /dashboard — the same values rendered live.
  • /api/v1/status — the same values as JSON, with the contract address and the last oracle timestamp.
  • The contract source and the basket file live in the public repository.

A copy of the index you compute from those values will match the on-chain number exactly, because the formula above is the only arithmetic involved.
